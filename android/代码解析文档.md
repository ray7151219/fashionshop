## 一、项目总体结构

```
com.example.fashionshop
├── FashionShopApp.java          // 应用入口（Application）
├── LoginActivity.java           // 登录页
├── RegisterActivity.java        // 注册页
├── MainActivity.java            // 主界面（底部导航 + 四个 Fragment）
├── ProductDetailActivity.java   // 商品详情页
├── CheckoutActivity.java        // 确认订单页（填收货信息）
├── PaymentActivity.java         // 模拟支付页
├── data/                        // 数据层
│   ├── SessionManager.java      // 登录态（SharedPreferences）
│   ├── CartManager.java         // 购物车存储
│   ├── OrderManager.java        // 订单存储
│   ├── ProductSizes.java        // 尺码推断
│   └── model/                   // 数据模型：Product / CartItem / Order / OrderItem / User / ApiResponse
├── net/                         // 网络层
│   ├── ApiConfig.java           // Mock / 真实后端开关 + 接口路径
│   ├── ApiClient.java           // UI 唯一入口，按开关分流
│   ├── HttpUtil.java            // HttpURLConnection + 线程池 + Handler
│   ├── MockApi.java             // 本地假数据
│   └── ApiCallback.java         // 回调接口
└── ui/                          // 页面
    ├── home/                    // 首页（HomeFragment + ProductAdapter）
    ├── cart/                    // 购物车（CartFragment + CartAdapter）
    ├── orders/                  // 订单（OrdersFragment + OrderAdapter）
    └── profile/                 // 我的（ProfileFragment）
```

**核心分层思想**：`Activity/Fragment` 只负责"界面展示 + 收集用户操作"，具体数据读写交给 `data` 层，网络请求交给 `net` 层。这样每个类的职责单一，好读也好改。

## 二、启动流程

1. 系统启动 App → 创建 `FashionShopApp`（因为 `AndroidManifest.xml` 里 `android:name=".FashionShopApp"`）
2. `FashionShopApp.onCreate()` 里调用 `ApiConfig.init(this)` 和 `MockApi.init(this)`，恢复"Mock / 真实后端"的数据源设置
3. 系统启动 `LoginActivity`（因为它在 Manifest 里声明了 `MAIN` + `LAUNCHER`）
4. `LoginActivity` 检查登录态：已登录直接进 `MainActivity`，否则显示登录界面
5. 登录成功 → 保存登录态 → 进入 `MainActivity` → 底部导航切换四个 Fragment

## 三、Activity 逐个详解

### 1. FashionShopApp.java（应用入口）

```java
public class FashionShopApp extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        ApiConfig.init(this);   // 恢复数据源设置（Mock / 真实后端）
        MockApi.init(this);     // 初始化 Mock 用户的 SharedPreferences
    }
}
```

**要点**：
- `Application` 是整个 App 的入口，比任何 Activity 都先创建，进程存活期间只有一份。
- 这里只做"一次性初始化"，不写业务逻辑。
- 为什么要在这里初始化？因为 `SharedPreferences` 需要 `Context`，而 `Application` 是最早能拿到 `Context` 的地方，且不会像 Activity 那样被销毁重建。

### 2. LoginActivity.java（登录页）

**职责**：校验用户名/密码 → 调网络层登录 → 成功后存登录态 → 跳转主界面。

#### 2.1 onCreate 的关键逻辑

```java
sessionManager = new SessionManager(this);
if (sessionManager.isLoggedIn()) {
    openMain();      // 已经登录过 → 直接进主界面，不再显示登录页
    return;
}

EdgeToEdge.enable(this);         // 内容延伸到状态栏/导航栏，实现沉浸式
setContentView(R.layout.activity_login);
```

**要点**：
- `sessionManager.isLoggedIn()` 判断是否已登录——这是"记住登录状态"的关键：只要之前登录过，重开 App 就直接进主界面。
- `EdgeToEdge.enable(this)` 让布局铺满全屏（含状态栏），配合 XML 里的 `fitsSystemWindows` 使用。

#### 2.2 数据源开关（Mock / 真实后端）

```java
MaterialSwitch sourceSwitch = findViewById(R.id.switch_login_mock);
sourceSwitch.setChecked(ApiConfig.USE_MOCK);
sourceSwitch.setOnCheckedStateChangeListener((button, checked) -> {
    if (loading || checked == ApiConfig.USE_MOCK) return;
    sessionManager.clear();              // 切数据源会清空登录态
    ApiConfig.setUseMock(this, checked);
    updateSourceLabel();
    requestLocalNetworkIfNeeded();       // 切到后端模式时申请本地网络权限
});
```

**要点**：
- 这个开关决定 App 走 **Mock 假数据** 还是 **真实 Tomcat 后端**。
- 切换数据源必须清空登录态，否则旧账号在另一数据源下会错乱。

#### 2.3 登录流程 attemptLogin()

```java
// 1. 本地校验（先拦一道，不发无意义的请求）
if (username.length() < MIN_USERNAME_LENGTH) {
    tilUsername.setError(getString(R.string.error_username_short));
    etUsername.requestFocus();
    return;
}
// 2. 调网络层
ApiClient.login(username, password, new ApiCallback<User>() {
    @Override public void onSuccess(User user) {
        if (isFinishing() || isDestroyed()) return;   // 页面已销毁就不更新 UI
        sessionManager.saveSession(user);             // 保存登录态
        openMain();                                    // 进主界面
    }
    @Override public void onError(String message) {
        if (isFinishing() || isDestroyed()) return;
        Toast.makeText(LoginActivity.this, message, Toast.LENGTH_SHORT).show();
    }
});
```

**要点（这是最值得学的几个点）**：
- **本地校验 + 服务端校验**：本地先检查用户名长度/密码长度，格式都不对就不请求了。
- **回调里先判 `isFinishing()/isDestroyed()`**：网络是异步的，返回时页面可能已经关了，不判断会崩溃。
- **`setLoading(true)` 防止重复提交**：请求期间禁用按钮、输入框，防止用户狂点。

#### 2.4 TextWatcher 实时清除错误

```java
private static void clearErrorOnInput(TextInputEditText editText, TextInputLayout layout) {
    editText.addTextChangedListener(new TextWatcher() {
        @Override public void onTextChanged(CharSequence s, int start, int before, int count) {
            layout.setError(null);   // 用户一输入，就清掉红字错误提示
        }
        @Override public void beforeTextChanged(...) {}
        @Override public void afterTextChanged(...) {}
    });
}
```

**要点**：`TextWatcher` 监听输入框文本变化；这里用于"用户开始改内容时清除错误提示"，体验更好。

### 3. RegisterActivity.java（注册页）

**职责**：与登录页几乎对称，多一个"确认密码"校验。

核心差异：

```java
if (!password.equals(confirmPassword)) {
    tilConfirmPassword.setError(getString(R.string.error_password_mismatch));
    etConfirmPassword.requestFocus();
    return;
}

ApiClient.register(username, password, callback);   // 注册成功后 finish() 回登录页
```

**要点**：
- 三个校验：用户名 ≥ 3 位、密码 ≥ 6 位、两次密码一致。
- 注册成功**不自动登录**，而是 `finish()` 回到登录页，让用户手动登录（更符合直觉，也便于演示）。

### 4. MainActivity.java（主界面）

**职责**：承载底部导航栏，切换首页/购物车/订单/我的四个 Fragment。

#### 4.1 登录态守卫

```java
SessionManager sessionManager = new SessionManager(this);
if (!sessionManager.isLoggedIn()) {
    goToLogin();   // 没登录 → 回登录页
    return;
}
```

**要点**：这是"未登录不能进主界面"的守卫。

#### 4.2 沉浸式 + 系统栏避让

```java
ViewCompat.setOnApplyWindowInsetsListener(root, (view, windowInsets) -> {
    Insets bars = windowInsets.getInsets(WindowInsetsCompat.Type.systemBars());
    fragmentContainer.setPadding(bars.left, bars.top, bars.right, 0);       // 内容避开状态栏
    bottomNav.setPadding(bars.left, bottomNav.getPaddingTop(), bars.right, bars.bottom); // 底部避开手势区
    return windowInsets;
});
```

**要点**：`EdgeToEdge` 之后内容会顶到状态栏/手势条下面，这段代码给容器加 padding 避开它们。

#### 4.3 底部导航切换 Fragment（核心）

```java
bottomNav.setOnItemSelectedListener(item -> {
    Fragment fragment = createFragment(item.getItemId());
    if (fragment == null) return false;
    getSupportFragmentManager().beginTransaction()
            .setReorderingAllowed(true)
            .replace(R.id.fragment_container, fragment)   // 用新 Fragment 替换容器内容
            .commit();
    return true;
});
```

```java
private Fragment createFragment(int itemId) {
    if (itemId == R.id.nav_home)    return new HomeFragment();
    if (itemId == R.id.nav_cart)    return new CartFragment();
    if (itemId == R.id.nav_orders)  return new OrdersFragment();
    if (itemId == R.id.nav_profile) return new ProfileFragment();
    return null;
}
```

**要点**：
- `BottomNavigationView` + `FragmentContainerView` 是最标准的底部导航写法。
- 每次点击导航项，`replace()` 把容器里的 Fragment 换成新的。
- `setSelectedItemId` 可以**程序化地**切换 Tab（比如支付页跳转到"订单"Tab 就是靠这个）。

#### 4.4 购物车角标

```java
public void updateCartBadge() {
    int count = CartManager.getTotalQuantity(this);
    if (count > 0) {
        bottomNav.getOrCreateBadge(R.id.nav_cart).setNumber(count);  // 显示数量角标
    } else {
        bottomNav.removeBadge(R.id.nav_cart);
    }
}
```

在 `onCreate`、`onResume` 里都调用，保证购物车数量变化后角标实时刷新。

#### 4.5 其他
- `EXTRA_OPEN_TAB` / `onNewIntent`：外部（支付页、结算页）通过 Intent 指定要打开的 Tab。
- `requestLocalNetworkIfNeeded()`：Android 17（API 37）起访问 `10.0.2.2` 需要 `ACCESS_LOCAL_NETWORK` 运行时权限。

### 5. ProductDetailActivity.java（商品详情页）

**职责**：接收首页传来的商品信息，展示图片/名称/分类/价格/描述，选尺码后加入购物车。

#### 5.1 用 Intent 传递商品数据

```java
public static Intent createIntent(Context context, Product product) {
    Intent intent = new Intent(context, ProductDetailActivity.class);
    intent.putExtra(EXTRA_ID, product.getId());
    intent.putExtra(EXTRA_NAME, product.getName());
    intent.putExtra(EXTRA_CATEGORY, product.getCategory());
    intent.putExtra(EXTRA_PRICE, product.getPrice());
    intent.putExtra(EXTRA_IMAGE_URL, product.getImageUrl());
    intent.putExtra(EXTRA_DESCRIPTION, product.getDescription());
    return intent;
}
```

**要点**：
- 静态工厂方法 `createIntent` 把"如何传参"封装起来，调用方（首页）只需 `startActivity(ProductDetailActivity.createIntent(ctx, product))`，不用关心字段名。
- 商品对象没有实现 `Serializable`，所以用**逐个字段 putExtra** 传递（更简单、更快）。

#### 5.2 读取并重建商品

```java
long id = intent.getLongExtra(EXTRA_ID, 0);
String name = intent.getStringExtra(EXTRA_NAME);
String category = intent.getStringExtra(EXTRA_CATEGORY);
// ... 逐个读取

Product product = new Product(id, name, category, price, imageUrl, description);
```

#### 5.3 动态生成尺码 Chip

```java
ChipGroup chipGroup = findViewById(R.id.chip_group_sizes);
String[] sizes = ProductSizes.forProduct(product);
for (String size : sizes) {
    Chip chip = new Chip(this);
    chip.setId(View.generateViewId());   // 动态生成唯一 id
    chip.setText(size);
    chip.setCheckable(true);
    chip.setClickable(true);
    chipGroup.addView(chip);
    if (sizes.length == 1) chip.setChecked(true);   // 均码商品自动选中
}
```

**要点**：尺码不是写死在 XML 里，而是根据商品类型（服装/鞋/围巾）用代码动态生成，更灵活。

#### 5.4 加入购物车

```java
btnAddCart.setOnClickListener(v -> {
    int checkedId = chipGroup.getCheckedChipId();
    if (checkedId == View.NO_ID) {          // 没选尺码
        Toast.makeText(this, R.string.select_size, Toast.LENGTH_SHORT).show();
        return;
    }
    Chip chip = chipGroup.findViewById(checkedId);
    String size = chip.getText().toString();
    CartManager.add(this, product, size);   // 交给数据层
    Toast.makeText(this, R.string.added_to_cart, Toast.LENGTH_SHORT).show();
});
```

**要点**：`getCheckedChipId()` 拿到当前选中的尺码；`View.NO_ID` 表示"没选中任何一项"。

### 6. CheckoutActivity.java（确认订单页）

**职责**：填收货人/手机号/地址 → 校验 → 生成待付款订单 → 跳支付页。

#### 6.1 恢复上次填的地址

```java
String scope = new SessionManager(this).getStorageScope();
SharedPreferences prefs = getSharedPreferences("fashion_shop_address", MODE_PRIVATE);
nameInput.setText(prefs.getString(scope + "_name", ""));
phoneInput.setText(prefs.getString(scope + "_phone", ""));
addressInput.setText(prefs.getString(scope + "_address", ""));
```

**要点**：收货信息存在 SharedPreferences，下次进来自动填上，避免重复输入。

#### 6.2 校验与下单

```java
if (name.length() < 2) { nameInput.setError(...); nameInput.requestFocus(); return; }
if (!phone.matches("1[3-9][0-9]{9}")) { phoneInput.setError(...); return; }  // 正则校验手机号
if (address.length() < 5) { addressInput.setError(...); return; }

Order order = OrderManager.createOrder(this, CartManager.getSelectedItems(this), name, phone, address);
if (order == null) { /* 失败提示 */ return; }

CartManager.removeSelected(this);   // 下单成功后，从购物车移除已结算的商品
// 跳转到支付页，带上订单号
Intent intent = new Intent(this, PaymentActivity.class);
intent.putExtra(PaymentActivity.EXTRA_ORDER_NO, order.getOrderNo());
startActivity(intent);
finish();
```

**要点**：
- 手机号用正则 `1[3-9][0-9]{9}` 校验（11 位、1 开头、第二位 3-9）。
- 下单 = 把购物车选中的商品"快照"成订单，然后从购物车移除。
- 用 `order.getOrderNo()` 把订单号传给支付页。

### 7. PaymentActivity.java（模拟支付页）

**职责**：展示订单金额/收货信息，选支付方式，模拟支付（只改本机订单状态）。

#### 7.1 页面刷新 refresh()

```java
Order order = OrderManager.findOrder(this, orderNo);
if (order == null) { Toast...; finish(); return; }   // 订单不存在就直接关页面

paymentAmount.setText(getString(R.string.price_format, order.getTotal()));
paymentAddress.setText(getString(R.string.shipping_summary, order.getRecipient(), order.getPhone(), order.getAddress()));

// 只有"待付款"订单能支付
paymentConfirm.setEnabled(OrderManager.STATUS_UNPAID.equals(order.getStatus()) && !processing);
paymentMethods.setVisibility(OrderManager.STATUS_UNPAID.equals(order.getStatus()) ? View.VISIBLE : View.GONE);
```

**要点**：根据订单状态动态控制按钮和支付方式是否可用——已付款/已取消的订单不能再付。

#### 7.2 模拟支付 confirmPayment()

```java
int selected = group.getCheckedRadioButtonId();
if (selected == -1) { Toast...; return; }   // 没选支付方式

String method = selected == R.id.payment_alipay ? getString(R.string.payment_alipay) : getString(R.string.payment_wechat);

new MaterialAlertDialogBuilder(this)
        .setTitle(R.string.payment_confirm_title)
        .setMessage(getString(R.string.payment_confirm_message, method))
        .setPositiveButton(R.string.payment_confirm_action, (dialog, which) -> {
            if (OrderManager.simulatePayment(this, orderNo, method)) {
                // 成功弹窗 → 查看订单
            } else {
                // 失败提示
            }
        }).show();
```

**要点**：
- `RadioGroup.getCheckedRadioButtonId()` 判断选中哪个单选按钮。
- `MaterialAlertDialogBuilder` 是 Material 风格的确认对话框。
- **模拟支付没有调用任何第三方**，只是 `OrderManager.simulatePayment` 把订单状态从"待付款"改成"待发货"。

## 四、主要 XML 布局详解

### 1. AndroidManifest.xml（清单文件）

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_LOCAL_NETWORK" />

<application android:name=".FashionShopApp" android:theme="@style/Theme.FashionShop"
             android:usesCleartextTraffic="true">
    <activity android:name=".LoginActivity" android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent-filter>
    </activity>
    <activity android:name=".RegisterActivity" android:exported="false" />
    <activity android:name=".MainActivity" android:exported="false" />
    ...
</application>
```

**要点**：
- `INTERNET` 权限：联网必须。
- `ACCESS_LOCAL_NETWORK`：Android 17 访问电脑后端（10.0.2.2）需要。
- `usesCleartextTraffic="true"`：允许 HTTP 明文请求（本地开发用，上线要用 HTTPS）。
- `LoginActivity` 的 `exported="true"` + `MAIN/LAUNCHER`：它是 App 的入口页面。
- 其他 Activity 都 `exported="false"`：只能被本 App 内部跳转，外部不能直接启动（更安全）。

结构：`ScrollView` → `LinearLayout`（垂直）→ 标题 + 输入框 + 按钮。

```xml
    android:inputType="textMultiLine"
    android:minLines="2"
    android:maxLength="120" />      <!-- 多行地址 -->
```

**要点**：
- `inputType="phone"`：弹出数字键盘。
- `inputType="textMultiLine"` + `minLines="2"`：地址框多行。
- `maxLength`：限制输入长度。

## 五、关键知识点总结

| 知识点 | 用在哪里 | 一句话说明 |
| --- | --- | --- |
| `EdgeToEdge` | 所有 Activity | 让布局铺满全屏（沉浸式） |
| `fitsSystemWindows` | 各布局根节点 | 配合 EdgeToEdge 自动避让系统栏 |
| `SharedPreferences` | SessionManager / CartManager / OrderManager | 轻量级本地持久化（存登录态、购物车、订单） |
| `Intent` 传参 | 首页→详情、结算→支付 | 页面间传数据 |
| `MaterialButton` / `TextInputLayout` | 登录、注册、结算 | Material 3 组件，自带圆角、错误提示 |
| `BottomNavigationView` | 主界面 | 底部导航，切换 Fragment |
| `FragmentManager.replace()` | 主界面 | 切换 Fragment |
| `RecyclerView` | 首页/购物车/订单 | 高性能列表（配合 Adapter） |
| `Glide` | 商品图 | 异步加载网络图片，带占位图/失败图 |
| `ChipGroup` | 尺码/分类选择 | 单选标签组 |
| `TextWatcher` | 登录/注册 | 监听输入变化（清错误提示） |
| `isFinishing()/isDestroyed()` 判断 | 所有网络回调 | 防页面销毁后更新 UI 崩溃 |
| 回调 + 子线程 + Handler | 网络层 | 网络请求不阻塞主线程 |

## 六、一张图看懂页面跳转关系

```
LoginActivity ──(登录成功)──> MainActivity
     │                            │
     └──(去注册)──> RegisterActivity
                                  ├── 首页 HomeFragment ──(点商品)──> ProductDetailActivity ──(加购)──> 购物车
                                  ├── 购物车 CartFragment ──(结算)──> CheckoutActivity ──(下单)──> PaymentActivity
                                  ├── 订单 OrdersFragment ──(去支付)──> PaymentActivity
                                  └── 我的 ProfileFragment ──(退出登录)──> LoginActivity
```

**数据流**：
- 商品数据：`net/ApiClient` →（Mock 或后端）→ `HomeFragment` 展示
- 购物车/订单：全程存在本机 `SharedPreferences`（`CartManager` / `OrderManager`），不依赖后端
- 登录态：`SessionManager` 存在 `SharedPreferences`，`isLoggedIn()` 判断是否已登录
